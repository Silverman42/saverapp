# Module 09 — Reversals and Financial Corrections

## Summary

Implement [Module 09](../modules/09-reversals-and-financial-corrections.md) in gated stages. A reversal is a full, immutable, linked compensation of an eligible posted Customer transaction and its required direct effects. One currently assigned Agent requests it; one Admin with `reversals.review` approves and posts it atomically. No transaction type may accept a live request or approval until its complete accounting, custody, evidence, and owner contracts are verified.

## Interfaces and invariants

- Named routes provide scoped list/detail, dependency preview, submission, same-operation lookup, requester cancellation, and Admin reject/approve-and-post. Vue uses Wayfinder. The server alone computes entries and money values; a disabled type cannot create a request or reach approval.
- A per-original posting-group row lock and unique live/posted target keys enforce at most one Pending review and one Approved-and-posted full reversal. Stable operation keys bind actor, action, target, and normalized payload. Same-key replay returns the authorized result; changed payload conflicts.
- A request stores the original and dependent identities/versions, full amount and components, category, internal reason, Customer-facing explanation, evidence, current task owner, and dependency preview. No financial effect exists until the Admin decision and complete balanced bundle commit in one transaction.
- Admin review uses Authentication's shared fresh password-and-MFA policy. Commit rechecks permission, restrictions, Customer status, owner versions, liability/reservations, physical-money disposition, and complete dependency graph. Unknown outcome resolves through the original operation key.
- Received money remains in controlled custody or an approved unapplied-funds account; a ledger reversal alone does not claim a return. Remittance reviews stay immutable, with any later linked exception owned by Module 07. Completed withdrawals require authoritative full payout disposition.
- Evidence defaults to at most three JPEG/PNG/WebP/PDF files of 5 MB each per record, with immutable supplements. File intake and live requests remain disabled until private storage, malware scanning, authorized retrieval, and retention/reveal policy are available.

## Approved defaults

Full reversal only; a correct replacement is separately confirmed with new identity and current timestamps. There is no arbitrary age cutoff or approved-but-unposted state. Compensation posts in the current period and retains the original occurrence date. One Admin reviews any value; no new role, generic journal, fee concession, or payout authority is introduced. The committed Module 08 staged workflow is the integration baseline and must be preserved.
