## Boundaries and operational contracts

- `AuditEvent::record()` creates the original compatibility ID and canonical event atomically; existing foreign keys continue to resolve. Compatibility payloads now contain only safe allowlisted facts. Protected values are separately encrypted and hidden from ordinary serialization.
- Canonical IDs, actor/category, approver, executor, permission/fresh-auth evidence, source/version, target/correlation and UTC occurrence/recording times are snapshots. Historical import keeps source occurrence time and separate import recording time, marks **Legacy evidence**, and records unavailable authority rather than reconstructing it.
- A canonical write failure rolls back the protected owner mutation. Dispatch/index failure leaves durable work. Producer operation keys replay identical inputs and raise a Critical case on changed content. Imports use unique legacy references and preserve unsupported records outside search.
- Search defaults to the last 24 hours of **recorded time**, ordered recorded timestamp/event reference descending. UTC date filters accept at most 366 inclusive days, with 25/50/100 rows. Actor, target, event/category, outcome/severity, source/permission/correlation and retention filters use safe exact fields. Source occurrence time is displayed independently on detail, particularly for imported evidence.
- Cursor encryption binds viewer, current permission version, filters, projection version, watermark and expiry. New watermark, changed grants/index or tampering requires a fresh search. Index gaps yield Partial results; exact canonical detail remains available. Detail access itself must capture successfully before content is returned.
- Rebuild processes at most 1,000 records per invocation (default 100), saves an isolated version/cursor and promotes only after content/schema and coverage checks. Current projection stays active during rebuild. Local SHA-256 content comparisons are **not** independently reviewed tamper verification.
- Case mutations lock current authority and case version. Active eligible security holders may own cases; bounded rotating scans release lost eligibility to the queue and increment version. Notes are separately encrypted. Audit evidence references also require `audit.view`; owner links independently authorize access.
- Cases cannot authorize financial operations, suspension, permission changes or recovery. Unlock remains Authentication-owned, with identity verification, no self-unlock/final-Admin bypass and a ten-minute authenticated expected-state token checked under user/matching-lock locks. Deadlocks retry at most three times and state is revalidated each attempt.
- Case/integrity notification snapshots are minimal, deduplicated and recipient-rechecked at materialization and retrieval. Read/delivery state never resolves the case. Authentication notifications keep their existing owner and are queued after commit.
- Payloads and notes currently use Laravel application encryption with recorded key identity. Separate production key custody/rotation, least-privilege database grants/trigger protection, immutable external checkpoints, legal policy and backup contracts require independent approval. Never rotate/drop keys or promote restored data using these local checks as certification.

## Interfaces and rollout

Named routes: `admin.audit.index`, `admin.audit.show`, `admin.security.index`, `admin.security.show`, `admin.security.update`. Case PATCH requires `expected_version`; Authentication unlock additionally requires `restriction_token`. The security workspace is independent of `audit.view` and offers only classified source facts and current permitted case content.

1. Apply additive migrations before deploying transactional producers and workers. The Module 14 migration was applied locally on MySQL; six append-only triggers were inspected. A pre-existing Authentication migration received a shorter explicit index name so fresh MySQL installs succeed.
2. Activate capture; run `php artisan audit:import-history --limit=100` repeatedly. This invocation imports at most 1,000 records and writes safe unsupported-schema diagnostics. No business actions or historical notifications run.
3. Run `php artisan audit:drain --limit=100` and `php artisan audit:rebuild --limit=100` until rebuild promotion. Recovery drain is scheduled every minute without overlap; owner-eligibility scans rotate through bounded batches.
4. Enable workspaces with `AUDIT_ENABLED=true` after the local readiness checks. The committed default is false; local readiness checks completed and the local environment now enables the workspaces. Set false to disable both workspaces while capture continues. Use the existing queue/scheduler. Local rollout imported seven safe historical records and promoted projection version 2.
5. Preserve original history, canonical/protected tables, case transitions, pending work and encryption keys. Production rollback uses forward fixes; **do not run destructive migration rollback** on evidence stores. Archive, expiry and restore promotion remain disabled.
