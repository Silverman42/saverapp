# Module 15 — Business Settings and Configuration implementation checkpoint

This is the staged implementation approved for safe import followed by owner certification. The supported configuration lifecycle is delivered; the complete Module 15 production acceptance gate remains blocked. Existing Module 13/14 work is preserved.

## Delivered behavior

- One trusted business identity; append-only encrypted configuration versions, events, operation results and consumer acknowledgements. Existing configuration imports at its actual version without manufacturing prior history.
- Active Admin baseline reads, exact current `business.settings.manage` for changes, actor-private drafts, strict catalogue validation and optimistic base/revision checks. Publication and cancellation require fresh password/MFA, confirmation and reason.
- Preview binds draft/base/dependency hashes and expires after ten minutes. Publication atomically records configuration, audit, activation work and notification intents. One pending bundle is allowed at a time; competing writers re-preview rather than merge unknown effects.
- Supported profile and presentation changes activate with explicit local consumer acknowledgements. Collection limits require future business midnight; the scheduled worker records actual activation time, blocks incompatible dependencies and retries safely. Rollback creates a new draft/version, including stable operation retries after the effective version advances.
- Runtime settings read authoritative database versions directly; no configuration cache is trusted. Collection batches capture configuration version. Existing committed attempts, history, batch freezing and reconciliation remain available while new financial capabilities are gated.
- Protected Inertia settings/diff/readiness/history screen, Wayfinder links and same-operation lookup/retry after unknown network outcomes. Mandatory notices retain Module 13 recipient reauthorization and safe summaries.
- `business:bootstrap` provisions only a fresh installation, accepts a privately supplied policy-valid permanent password through hidden prompt or private file, seeds explicit Admin grants and requires the existing MFA enrollment flow. It refuses existing users/imports and supplies no default password.

## Local rollout and verification

The additive migration and `business:import-settings --no-interaction` were applied locally, importing version 1. Existing accounts were retained; bootstrap was not run on this installation. Imported safe defaults disable new collections, customer registration, plan creation, payout, reversal and file export capabilities pending owner certification. This is a deliberate change from permissive legacy environment flags.

Local evidence: 53 focused settings/bootstrap tests, 349 affected feature tests (2,244 assertions), and three isolated MySQL process races (15 assertions). Races cover competing publications, same-operation retry and activation/cancellation. Scoped PHPStan, Vue type checking, production build and Pint were run. Browser navigation reached login; authenticated responsive, keyboard and assistive-technology verification is pending. The complete PHP suite remains a separate user-run check.

## Remaining owner gates

Timezone changes, method/account mapping enablement, provider finality, emergency withdrawal disable races, historical/open-record migrations, verified outbound sender/contact use, logo storage, emergency bootstrap recovery key, retention/backup/restore, production load and complete accessibility/security evidence remain Blocked. Financial dashboard range and branding fields remain read-only until their consumers are certified. No unavailable integration is reported as effective or replaced with a fallback.

Commands: `business:activate-settings --limit=100` is scheduled every minute; `business:import-settings` is idempotent. Scheduler deployment and production recovery evidence belong to Module 16. Database rollback requires a reviewed forward migration; do not drop immutable published history.
